# 案例审核 Skill v1.0

## 功能说明

对思政案例库入库前的案例进行系统化审核，分为**硬审核**（自动化格式合规检查）和**软审核**（AI 辅助风险高亮）。

审核目标：将机械性格式检查自动化，将价值判断类审查留给人工复核，提升审核效率的同时不降低质量标准。

---

## 审核流程

```
案例提交
    │
    ├── 硬审核（自动化，无需 LLM）
    │       ├── 字数检查
    │       ├── 必填字段检查
    │       ├── 结构完整性检查
    │       ├── 讨论问题数量检查
    │       ├── 素材来源检查
    │       └── 负面案例出口检查
    │       └── 评分（0-100）
    │
    ├── 软审核（AI 辅助，调用 LLM）
    │       ├── 风格风险评估
    │       ├── 表述风险高亮
    │       ├── 事实存疑标记
    │       └── 教学价值评估
    │       └── 不自动拦截，仅标记提醒
    │
    ├── 事实核查（可选，如有 URL/引用）
    │       └── 调用 fact_verification 模块
    │
    └── 生成审核报告
            ├── 硬审核结果与评分
            ├── 软审核发现项
            ├── 事实核查结果
            └── 综合评估与建议
```

## 硬审核标准（自动化）

### 1. 字数检查
- **标准**：案例正文（不含元数据、信息卡、讨论问题等附加部分）应在 **500-3000 中文字符**之间
- **方法**：统计 `[一-鿿]` 范围内的字符数
- **通过条件**：500 ≤ 字数 ≤ 3000

### 2. 必填字段检查
以下字段必须在案例中存在且非空：
- 案例标题
- 适用课程（或适用课程/场景）
- 素材类型
- 素材性质（正面典型 / 负面案例 / 中性素材）
- 主打思政主题

### 3. 结构完整性检查（按模板类型）

根据案例内容中的关键词自动判断模板类型，并检查对应必含结构：

| 模板类型 | 判断关键词 | 必含结构 |
|---------|-----------|---------|
| **模板A（标准叙事型）** | 情境还原、冲突与抉择 | 情境还原、冲突与抉择、行动与结果、思政映射、讨论问题 |
| **模板B（现象-本质-价值型）** | 现象层、本质层 | 现象层、本质层、价值层、讨论问题 |
| **模板C（比较分析型）** | 对比维度、比较分析 | 对比维度设置、思政落点 |
| **模板D（问题反思型）** | 事件客观呈现、多元视角 | 事件客观呈现、多元视角还原、原因分层分析、制度回应/纠错过程、思政价值点提炼、讨论问题 |

> 注：结构检查采用关键词存在性判断，不要求严格分段标题匹配。

### 4. 讨论问题数量检查
- **标准**：至少包含 **2 个** 讨论问题
- **方法**：在"讨论问题"相关章节中，统计以 `-`、`•`、`1.`、`（1）` 等标记开头的条目数

### 5. 素材来源检查
- **标准**：案例中必须注明素材来源
- **方法**：检查内容中是否包含"素材来源"、"来源"、"原文链接"、"参考"等关键词

### 6. 负面案例出口检查
- **标准**：若素材性质为"负面案例"，必须包含"制度回应"或"纠错过程"
- **方法**：检查内容中是否包含"制度回应"、"纠错"、"改进"、"处理结果"等关键词

## 软审核标准（AI 辅助）

软审核由 LLM 完成，标记疑似问题但不做出通过/不通过判断。

### 审核维度

1. **风格风险（style_risk）**
   - 过度宣传、拔高渲染
   - 说教式表达（"这充分说明了…"、"我们必须…"）
   - 口号化、标语化语言
   - 严重程度：`suggestion` / `concern` / `warning`

2. **表述风险（phrasing_risk）**
   - 可能引发歧义的表述
   - 涉及敏感话题但未做充分说明
   - 价值判断过于绝对
   - 严重程度：`suggestion` / `concern` / `warning`

3. **事实存疑（factual_concern）**
   - 引用的数据、日期、政策文件缺少明确来源
   - 关键事实陈述无法追溯
   - 统计数据未标注出处
   - 严重程度：`suggestion` / `concern` / `warning`

4. **教学价值（teaching_value）**
   - 讨论问题设计是否有效引发思考
   - 案例与知识点的联结是否自然
   - 是否具有多视角分析空间
   - 严重程度：仅 `suggestion`

### 严重级别定义

| 级别 | 含义 | 处理方式 |
|------|------|---------|
| **suggestion** | 优化建议 | 供参考，不影响审核结论 |
| **concern** | 存疑关注 | 建议人工复核 |
| **warning** | 风险警告 | 强烈建议修改后再提交 |

### 重要原则

**软审核绝不自动拦截。** 所有发现项均以高亮形式呈现给人工审核员，由人工做出最终判断。

## 事实核查集成

当案例内容中出现以下情况时，自动触发事实核查：
- 明确的 URL 链接
- 提及具体政策文件名称（如《xxx纲要》《xxx办法》）
- 包含具体统计数据但未标注来源

调用 `fact_verification.verify_claim()` 进行验证，结果纳入审核报告。

## 审核报告输出格式

```json
{
  "case_id": "案例编号或标题",
  "case_title": "案例标题",
  "hard_result": {
    "passed_all": true/false,
    "checks": [
      {"name": "字数检查", "passed": true, "message": "...", "detail": {...}}
    ],
    "score": 85
  },
  "soft_result": {
    "findings": [
      {
        "category": "style_risk",
        "severity": "concern",
        "description": "...",
        "location": "价值层段落",
        "recommendation": "..."
      }
    ],
    "finding_count": 2,
    "has_warnings": false
  },
  "fact_result": {
    "verified_claims": [...],
    "unverified_claims": [...]
  },
  "overall_status": "passed/needs_review/rejected",
  "timestamp": "2026-05-15T10:00:00",
  "report_md": "# 审核报告\n..."
}
```

### 综合状态判定规则

| 条件 | 状态 |
|------|------|
| 硬审核评分 < 60 | **rejected**（格式严重不合格，自动退回） |
| 硬审核评分 ≥ 60，但存在软审核 warning 或事实核查失败 | **needs_review**（需人工复核） |
| 硬审核评分 ≥ 80，无软审核 warning，事实核查通过 | **passed**（审核通过） |
| 其他情况 | **needs_review**（默认人工复核） |

## 延迟实现项（Deferred）

以下功能在当前 alpha 版本中**不实现**，留待后续迭代：

1. **政治方向自动检测**
   - 原因：过于敏感且主观，当前 LLM 能力不足以可靠判断
   - 替代方案：由人工审核员进行政治标准把关

2. **当事人确认工作流**
   - 原因：属于业务流程而非技术审核
   - 替代方案：在人工审核阶段由管理员协调

3. **完整语义结构分析**
   - 原因：alpha 版本采用关键词匹配，精确的段落结构分析需要更复杂的 NLP
   - 替代方案：后续引入段落级解析
